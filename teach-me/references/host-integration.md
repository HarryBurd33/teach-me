# Host capabilities and real learning evidence

The core skill and local helpers require no account credentials, paid provider,
microphone, service or external application. Discover actual tools before proposing
an optional integration. A skill instruction does not install or grant any of them.

| Capability | Supported workflow | What must be checked in the actual host |
| --- | --- | --- |
| Dictation | Accept a host-produced transcript as learner text; keep confidence and help separate | Learner chooses the microphone/transcription feature and understands where audio is processed. Teach-me supplies no speech-recognition engine or accuracy guarantee. |
| Audio/video/images | Inspect through available authorized media tools; otherwise use text/self-report | Whether this attachment can actually be inspected. Never infer tone, timing or physical technique from an inaccessible file or transcript alone. |
| Reminders | When the learner requests one with a time, use a supported host reminder/automation tool | Actual tool availability, target/timezone and result. A suggested review interval or local run log is not a scheduled reminder. Do not install a service or create recurring work merely because the learner saves a journey. |
| Model/provider integration | A learner may explicitly configure an existing provider tool or local command for a bounded project | Account/privacy, current terms, authorization and enforced spending boundary. Never infer API credit from a subscription, copy credentials into plans, or silently fall back to paid API use. |
| Device transfer | Use the verified journey archive procedure | Independent destination access and tools. An archive transports data, not permissions, credentials, processes or live ownership. |

The [local runner](local-runtime.md) makes explicit local experiments executable;
it does not turn these host capabilities into bundled services. For a reminder or
provider, report actual installation/execution separately from a design or a
proposed command. Never claim a microphone, reminder or API was tested when it was
not. Hazardous physical skills still need appropriate qualified supervision and
cannot be certified remotely by adding more software.

## Pilot learning effectiveness

Use the [pilot template](../templates/learning-pilot.md) only when the learner wants
to test the teaching approach. Begin with an observable ability, a short baseline
task, a comparable later task, and a delayed retention/transfer task. State the
conditions, assistance, source and whether performance was actually inspected.
Avoid using an identical memorized answer as evidence of general transfer.

Ask before collecting unnecessary personal data or involving other participants.
Save an authorized pilot as `learning-pilot.md` beside the journey records; its bytes can be included in the allowlisted manual transfer. Keep a minimal local record; do not publish learner results without explicit
permission. A source export or simulated learner is not a consenting participant.
Mark not-yet-run checks pending and keep unknown values unknown; a confidence of
zero stays zero. Do not schedule a delayed test unless the learner requests an
actual supported reminder.

Inspect the learner's responses and record narrow evidence in the existing progress
schema; no new mastery field is introduced. Missing results remain missing. If
conditions or help differ, describe the confound rather than claiming an effect.
One learner's improvement is not a controlled causal study, and a passed retention
task is evidence only for that ability, interval and setting. Stronger efficacy
claims require appropriate independent studies and real follow-up; those cannot
be manufactured by software tests or completed during this release build.
