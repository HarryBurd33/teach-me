# Teach-me v0.8.0

## Plan and result

The previous release could edit graphs only through JSON/CLI patches. This release adds an offline graph draft editor, preserves the existing normalized data contract and CLI behavior, and tests the browser-to-new-file round trip before installation. Unrelated trust, sync and learning-efficacy gaps remain explicit rather than being represented as solved.

Render a graph with `python3 teach-me/scripts/graph_editor.py render --input graph.json --output editor.html`. Open the generated file, stage changes and export the draft. Run `check --base graph.json --draft draft.json`, review its output, then `apply` with the exact draft SHA256, `--approve` and a new output path. See the [editor guide](../teach-me/references/graph-editor.md).

## New capabilities

Edit claim names and statements; add/delete claims; edit argument premises/conclusions; preserve jointly required AND premises; search IDs, text, aliases and historical provenance; see staged changes; reset to the base; explicitly download a strict hash-bound draft. Existing IDs are immutable while editing. Deleting referenced claims refuses without cascading. Existing metadata survives; new records have empty creation timestamps and no invented provenance.

The self-contained page bundles its CSS and JavaScript with exact CSP hashes. Labels are text, and there are no remote assets, network calls, browser storage, autosave or source writeback paths. CLI checking and approved create-new application bind the exact base and raw draft bytes, recheck sources and preserve the original graph. Manually changed assertions do not gain truth, source verification, authorship or mastery claims.

## Test results and evidence

All **366 tests passed** against both the candidate and global installation:302 prior regressions,38 backend checks,3 frontend static/DOM-adapter checks and23 independently frozen contract methods. Portable test copies change only root selection; originals, hash records and adapters are retained. Native enabled user-scope discovery passed from two directories without an inference turn. All45 installed skill files match the accepted candidate; v0.7.0 is preserved locally for rollback.

Actual Chrome UI testing edited a claim, added a claim and an AND argument, refused referenced deletion, verified search/reset, displayed hostile markup literally with zero image elements and no observed alert, and exported a real downloaded JSON file. The downloaded draft passed CLI checking and applied to a new graph with metadata and original bytes preserved. The preview served only one synthetic document from memory at loopback and was stopped after testing. Direct file navigation was blocked by browser automation policy, so file-opening behavior itself was not browser-tested. A download-event waiter timed out despite the verified Downloads file. Browser network tracing was unavailable; offline claims are supported by static asset/CSP checks, not a captured network trace.

Independent review found no blocking issues and confirmed old CLI equivalence. Four literal workflow responses per arm scored baseline3/4 and candidate4/4 in one nonblind shared evaluator context with effective model/effort unknown. These narrow examples do not establish causal model superiority or learning gains. macOS temporary-directory symlink rejection required canonical TMPDIR; a mistaken browser select assumption was corrected after inspecting the actual input. Original failures remain in reports.

## Remaining limitations and next steps

| Area | What remains | Next step |
| --- | --- | --- |
| Editor scope | Graph-only normalized documents;256 claims/arguments and2MiB inputs; no session, alias or provenance editing; no undo history or autosave | Add versioned larger-graph and session-edit contracts only with explicit preservation/recovery rules. |
| Browser/platform qualification | Actual UI coverage is Chrome on macOS using a confined HTTP preview; no Windows, Safari, Firefox or direct file-opening trial | Run the frozen browser round trip on those targets; test keyboard/screen-reader/responsive behavior with users. |
| Learning and semantics | No actual learner outcomes or automatic truth/inference verification | Run consenting baseline, retention and transfer trials with assistance/confounds recorded. |
| Model reliability | Shared-context nonblind workflow examples; no broad qualified native automatic selection | Use independent model/effort contexts and preserve frozen cases and failures. |
| Trust | No authenticated reviewer identity or external trust anchor; a full-store malicious rewrite is outside guarantees | Specify signatures, key management and recovery before implementing signed records. |
| Incomplete backups | Incomplete archives, abandoned locks/stages and uncertain owners still fail closed | Develop a platform-tested reconstruction protocol after resolving actual owner/process outcomes. |
| Storage/integrations | No cloud/background sync, encryption, arbitrary attachments, universal native format support or guaranteed provider/reminder/media access | Define privacy, conflict and recovery contracts per integration before implementation. |
| Filesystem/runner | Cooperative locks do not fence hostile writers; no universal power-loss durability or Windows/detached-child guarantee; runner inherits host permissions | Run target filesystem/platform fault trials and add a defined isolation boundary. |
| Separate host guard | Teach-me does not implement the installed checkpoint guard maintenance allowlist | Repair that host workflow independently; no guard bypass is bundled here. |

Existing journeys need no migration. Replace the whole skill folder together. MIT licensing and existing repository topics remain.
