# Teach-me v0.10.0

This release adds conservative same-base graph draft reconciliation. It combines independent whole-record changes, preserves metadata and jointly required premises, exposes conflicts and requires exact reviewed hashes and explicit choices before creating a new v1 draft. See the [workflow guide](../teach-me/references/draft-merge.md). Existing Python helpers, editor assets and data formats remain unchanged. All **475 checks passed** against both the candidate and global installation:397 prior checks,33 constructor methods and45 independent methods. All **49 skill files** match the accepted candidate. Native enabled user-scope discovery passed from two directories through the already-running daemon; no server or model turn was started. v0.9.0 is retained locally for rollback.

The workflow is structural and local: it does not merge different bases or arbitrary sessions/files, infer field-level intent or semantic truth, authenticate reviewers, autosave or synchronize devices. Never-exported work remains unrecoverable. Real learning outcomes, installed Safari/screen-reader user studies, incomplete-archive reconstruction, identity/key recovery, encrypted/distributed transport, stronger execution isolation and universal filesystem durability remain separate work.


## Implemented behavior

`scripts/draft_merge.py plan` compares complete base/left/right records. Identical or one-sided edits combine; divergent edits, delete/edit cases and different new records under the same ID become explicit `both-edited` conflicts. Cross-branch missing endpoints and capacity overflow promote affected changes to `dependency` or `capacity` conflicts. Choices select a complete base/left/right record; selecting an absent record deliberately drops it. No field-level intent or semantic merge is inferred.

`apply` requires the exact raw plan and decisions SHA256, complete choices bound to that plan, and a freshly recomputed matching plan from the same source bytes. It validates the resulting graph and emits a normal strict v1 draft into a new file. All five sources are rechecked during atomic publication. Unknown fields, duplicate JSON, malformed IDs/choices, metadata changes, stale/tampered inputs, sensitive/symlink/traversal paths, logical duplicates and size/count overflow refuse. All original sources and foreign output files remain preserved. Existing records retain aliases, timestamps and provenance; new records use blank metadata. Joint premises remain jointly required.

The output can be pasted into the unchanged offline editor, reviewed, exported and checked/applied to a new graph. All13 prior Python helper files,3 editor assets and33 prior test files remain byte-identical. Existing progress, transfer, graph and draft schemas remain unchanged. The new plan/decisions contracts are separate optional formats. No new installed dependency, account access, background service or API spend is introduced.

## Test evidence and limits

Forty independent methods were frozen before candidate inspection; all passed. Five additional post-inspection methods extend independent node/node, same-record whole-value conflict, chain-count/byte capacity and plan-size coverage; they are labeled separately. Targeted failure tests changed each of the five inputs after staging, raced a foreign destination and injected fsync failure. These establish the exercised cooperative safeguards, not hostile-writer fencing or universal durability.

The prior version lacks the merge module:31 positive checks fail and9 negative subprocess checks pass from absence alone. Those negative results supply no baseline security credit. The intended behavioral benefit is executable reconciliation of independent drafts and explicit conflict decisions. No model superiority or learner-efficacy trial was performed.

Three new frozen browser cases per project extend the existing four. The required remote matrix covers Linux Chromium/Firefox/WebKit and Windows Chromium:28 expected executions. Cases use real file URLs, actual downloads and CLI check/apply, preserve original bytes, inspect full metadata/AND premises, resolve a whole-record conflict and exercise refusal. Final tagged-release notes record actual CI results, exact commit and browser versions. Browser discovery/syntax checks alone are not reported as browser passes.

[Combined results](../validation/v0.10.0/combined-tests.json), [installed results](../validation/v0.10.0/installed-tests.json), [independent review](../validation/v0.10.0/review/report.md), [browser cases](../browser-tests/draft-merge.spec.js), [test-porting record](../validation/v0.10.0/test-porting.json), and [original/published evidence hashes](../validation/v0.10.0/public-evidence-hashes.json) preserve the evidence. ## Remaining work

| Area | Boundary and next step |
| --- | --- |
| Merge scope | Exact same complete graph base only; whole records only. Different-base, field-level, session/native-store and arbitrary attachment merging need separate contracts. |
| Incompatible combinations | Final validation can still refuse selected choices. Different IDs carrying the same logical argument are not silently deduplicated; revise a branch and regenerate the plan. |
| Size and editing |2MiB base/branch/decision/output-draft,8MiB plan,256 claims/arguments. No autosave, native writeback, semantic search or recovery of never-exported work. |
| Learning evidence | Run consenting real baseline, retention and transfer pilots with assistance/confounds recorded. Software tests do not establish learning gains. |
| Accessibility/platforms | Real screen-reader/user studies and installed Safari/Edge/Firefox versions still need qualification. Playwright WebKit is not Safari; Windows browser tests do not qualify the entire Python runner/filesystem stack. |
| Trust and storage | Define reviewer identity, keys/revocation/recovery and private transport/conflict rules before adding signatures, encryption or distributed sync. |
| Recovery/isolation | Incomplete archives, uncertain locks, hostile writers and universal power-loss durability remain outside guarantees. Preserve artifacts and define platform-tested reconstruction/isolation protocols before implementation. |
