# Teach-me v0.9.0

This release adds bounded staged undo/redo, deliberate saved-draft re-import, keyboard/focus refinements and an executable browser acceptance suite. The [recovery guide](../teach-me/references/editor-recovery.md) explains scope, limits and safe recovery. All **397 tests passed** against both the candidate and global installation:366 prior checks,13 construction checks and18 independent contracts (17 original frozen plus1 observed-failure regression). All **46 skill files** match; native enabled user-scope discovery passed from two directories without inference. v0.8.0 is preserved locally for rollback. Actual local Chrome checks and the remote browser matrix are distinguished below.

Existing progress/transfer schemas, Python commands and graph draft version1 remain unchanged. The editor remains offline with explicit export/check/apply into a new file; manually edited claims do not become verified source evidence or mastery.

The larger roadmap remains: consenting real learner retention/transfer pilots; authenticated reviewer identity with key/revocation/recovery design; a reviewed incomplete-archive reconstruction protocol; privacy/conflict/recovery contracts before cloud sync/encryption; broader host and filesystem fault qualification. No automated test substitutes for learner or screen-reader user evidence. Playwright WebKit is not Safari qualification, and Windows browser checks do not qualify the entire Python runner/filesystem stack.


## Evidence and release gates

Undo/redo stores at most20 staged graph snapshots and8MiB across undo/redo. Reset and a valid import are undoable; a successful new edit clears redo. History excludes unsubmitted text and disappears at page close. Explicit pasted re-import validates strict JSON, duplicate keys, depth, schema, original base digest, metadata and bounds before replacing staged work. Refusals preserve graph/history/exported bytes. Full record metadata and AND premises survive restoration. The Python/draft/progress/transfer formats remain unchanged.

Independent frozen contracts all failed on v0.8 because the new controls were absent, then passed on the candidate. This distinguishes the added capability; missing-control baseline failures supply no comparative security credit. Review caught floating version tokens accepted by browser JSON but refused by Python; the minimal lexical parser repair and supplemental checks are preserved. No model-superiority or learner-efficacy comparison was performed. Developer tests use Node and pinned Playwright1.64.1; the installed skill gains no package dependency.

[Combined checks](../validation/v0.9.0/combined-tests.json), [installed checks](../validation/v0.9.0/installed-tests.json), [independent review](../validation/v0.9.0/review/report.md), [browser suite](../browser-tests/editor.spec.js), [local browser check](../validation/v0.9.0/browser/results.json), [test adapter record](../validation/v0.9.0/test-porting.json) and [original/published hashes](../validation/v0.9.0/public-evidence-hashes.json) retain the evidence. Required remote browser gates run4 cases each on Linux Chromium/Firefox/WebKit and Windows Chromium; the final tagged release records their actual results and browser versions from CI logs. No skipped browser case counts as passed.

The separate checkpoint resume issue was an omitted `web` capability declaration. Supported review/resume with the actual `python`, `filesystem`, `web` set succeeded without changing checkpoint requirements or disabling guards. Teach-me does not bundle that host guard.

## What still needs work

Direct installed Safari/Firefox/Edge versions and real assistive-technology users still need qualification. Linux Playwright WebKit is not Safari. Remote Windows browser testing is narrower than full Windows Python-runner/filesystem qualification. The editor remains graph-only, bounded to256 claims/arguments and2MiB inputs. It does not edit sessions, provenance or aliases, autosave, merge divergent drafts, write back to native sources or provide semantic search/validation. Loss of never-exported work is unrecoverable. Cooperative filesystem checks do not fence hostile writers or guarantee universal power-loss durability.

Next steps: run consenting baseline/retention/transfer learning pilots; qualify screen readers and target installed browsers; define signed-review identity/key/revocation/recovery; specify incomplete-archive reconstruction before enabling it; and define privacy/conflict/recovery boundaries before adding sync or encryption. These need explicit user participation or design decisions, not fabricated automated passes.
