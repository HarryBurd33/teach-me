# Teach-me v0.3.0

## Implementation plan and delivered scope

1. Implement a read-only native-v1 session/graph adapter and normalized report; test source preservation, joins, confidence, versions and malformed input.
2. Add a safe searchable offline argument-map viewer; preserve joint premises, provenance and missing-endpoint warnings.
3. Add bounded allowlisted journey archives, fresh-destination import and cooperative local writer locks; test concurrency, tampering and rollback.
4. Add an explicit local argv DAG/retry runner; test validation, gates, failure/timeout/output bounds and interruption.
5. Add capability-aware host guidance and a real-learner baseline/retention/transfer pilot template.
6. Independently review and execute examples, run release/install checks, preserve rollback and publish only accepted files.

Progress schema v1 remains unchanged. New helpers are optional Python 3.9+ standard-library tools; no upstream app, service, account credentials or paid API client is installed. New files and contracts are linked from the [skill README](../teach-me/README.md).

## Remaining boundaries and next steps

| Boundary | What v0.3.0 supplies | What still needs separate work |
| --- | --- | --- |
| Native data compatibility | Tested subset of pinned native-v1 sessions/graphs, explicit unsupported/error outcomes | More representative real exports and legacy dialects; upstream writeback needs its own scope/rights/roundtrip tests |
| Graph workflows | Searchable local argument-card viewer with grouped premises and provenance | Automatic semantic extraction from prose, graph editing/layout and semantic search need a model/data design and independent correctness checks |
| Device/workspace continuity | Verified manual archive/import and cooperative local writers | Continuous/distributed sync, conflict merge and atomic edits across all files remain unimplemented; old/manual writers do not honor locks |
| Harness runtime | Sequential DAG execution, bounded retries, explicit gates and logs | Autonomous planning, arbitrary routing/fan-out, scheduler/provider adapters and crash resume need separately verified host mechanisms and authorization |
| Execution containment | Owned POSIX group cleanup and explicit uncertain failures | This is not an OS sandbox; detached descendants may escape; Windows descendant cleanup/native deployment remain unverified |
| Host features | Explicit capability checks for media, dictation, reminders and providers | Actual host integration/access, microphone processing/privacy, requested schedules and paid-use budgets must be resolved per journey |
| Learning effectiveness | Local pilot template with baseline, later, retention and transfer checks | Consented real learners and delayed observations; no software release can manufacture those results or certify hazardous physical readiness |
| Storage/delivery | Progress backup, validated archives and hash checks | No encryption, authenticated signature, automatic stale-lock theft or universal power-loss guarantee; a hard stop can leave a new report incomplete |

No extra setup is needed for the included text/local workflows beyond available Python/browser tools. Use a new approved destination for imports. Review plans before execution; commands inherit host access and a passing command need not be a meaningful test. Use qualified supervision for hazardous physical skills.
