# Teach-me v0.7.0

This release adds explicit historical-receipt import and verified recovery of interrupted snapshot removals. It addresses two v0.6.0 gaps while preserving the teaching workflow, progress schema v1 and journey transfer formats v1/v2.

## Plan and behavior

1. Import selected old receipts with an exact hash, journey ID, expected history tip and reason. Preserve their original bytes and judgment, but label them historical and never promote them to current readiness.
2. Validate a complete retirement archive and create a fresh recovery plan bound to the current store and archive bytes. Protect current HEAD and previous, then finish only the selected removals still pending under explicit apply.
3. Run component, independent failure and existing regression checks. Install the accepted candidate with rollback and verify CI plus immutable source/release downloads.

[Review history](../teach-me/references/review-history.md) continues writing existing six-key v1 entries for current, journey-checked appends. Imported v2 entries add `origin: "historical_import"` and `origin_note`; mixed chains are readable and older entries are never rewritten. The raw receipt remains extractable. Status distinguishes the original receipt's readiness flag from the imported entry's historical-only effect. Old v0.6.0 readers reject v2 history entries, so update the receiving skill before reading a mixed store. The separate history store is still outside journey ZIPs.

[Snapshot recovery](../teach-me/references/snapshot-recovery.md) accepts only a complete canonical archive with all selected ZIPs verified against their names, metadata and original journey identity. The current store is independently validated, including current HEAD/previous. A new plan lists `remaining` and `already_absent`; absence does not prove who removed a file or why. New unrelated revisions may coexist when protection and identity checks still pass.

Recovery plans bind exact current store and archive hashes. Applying a stale plan, changed/corrupt/incomplete backup or newly protected selection fails before new removal. A completed operation can be verified as a no-op. If another interruption occurs, retain the archive and inspect a fresh plan rather than replaying the old one. No background recovery, archive reconstruction, stage cleanup or lock theft is added.

These tools record structural and byte-level checks. Imported origin and reviewer roles are operator claims, not authenticated identity. Neither a receipt, hash chain nor recovery plan certifies semantic truth, learner mastery or permission to execute another task.

## Validation

All **302 tests passed** against both the candidate and global installation: 238 unchanged regressions, 27 historical-import cases, 17 recovery cases and 20 independently frozen groups. Five independently reviewed critical files retain their reviewed hashes; all40 installed files match the accepted candidate. Native enabled user-scope discovery succeeded from two directories without a model turn, and v0.6.0 is preserved locally for rollback.

The independent checks imported/extracted exact whitespace-preserving old receipts without promoting readiness; exercised a mixed v1/v2/v1 chain; and completed actual interrupted maintenance and repeated recovery failures while preserving protected and backup bytes. Stale plans, modified/incomplete archives, newly protected selections, wrong hashes/IDs, unknown files and held locks were refused. A completed operation produced a verified no-op. Reverse ancestry was separately covered by static inspection; the reviewer did not claim exhaustive size/symlink/race permutations.

Four literal model responses per arm were recorded by one fresh delegated evaluator. Both arms met all four boundary checks; requested native capabilities were present in four candidate cases versus two baseline cases. The evaluator generated and graded both arms nonblind in one comparison context with effective model/effort unknown. These are narrow workflow examples, not learner outcomes or causal gains.

The recovery component initially expected a different existing API exception class for corrupt ZIPs; the corrected expectation and original result are retained. The independent runner initially had two fixture setup errors, corrected without changing the frozen expectations. The full regression adapters retain original helper bodies and AST-extracted check expressions.

[Integrated results](../validation/v0.7.0/combined-tests.json), [independent review](../validation/v0.7.0/review/report.md), [porting record](../validation/v0.7.0/test-porting.json) and [original/public evidence hashes](../validation/v0.7.0/public-evidence-hashes.json) document the checks and redactions. Public CI and immutable source/release download checks are recorded with the final tagged release.

Local publication was interrupted by an independent checkpoint guard: its maintenance allowlist blocked metadata edits and the documented retry command. The user repaired private metadata and invoked that retry, then the supported10percent grant/review/resume succeeded. Teach-me does not bundle this guard; stopped-state maintenance remains a separate host-workflow repair. Historical failures and partials remain preserved in earlier reports. Software checks and simulated model examples do not establish real learning gains.

## Remaining limitations and next steps

| Area | Remaining work | Next step |
| --- | --- | --- |
| Learning and meaning | Actual learner outcomes, domain/source judgment | Run consenting baseline, independent application, retention and transfer checks; record assistance, confounds and limits. |
| Model reliability | Broader independent contexts and native automatic selection | Use frozen cases with separately qualified model/effort contexts and preserve failures; explicit instruction loading is a different check. |
| Identity and trust | Authenticated reviewers and an external trust anchor | Define identity, signatures, keys and recovery requirements before implementing signed records. A malicious full-store rewrite is outside the current guarantee. |
| Incomplete-backup recovery | Rebuilding incomplete publication or safely resolving abandoned locks/stages | Preserve every artifact, establish actual owner/process outcomes and specify a platform-tested reconstruction protocol. No automatic cleanup. |
| Storage and transport | Distributed/background sync, encryption, arbitrary attachments | Define privacy, migration, conflict and recovery contracts before adding a service. Separate stores require explicit reviewed private transport. |
| Native formats and UI | More legacy/native formats, writeback, semantic search and interactive graph editing | Add versioned synthetic fixtures and review reuse rights/compatibility for each format or interface. |
| Host execution/integrations | Stronger isolation, Windows/detached children and verified media/reminder/provider access | Test the target host, obtain applicable authorization and spending bounds; the runner inherits host permissions. |
| Filesystem durability | Hostile races, unsupported hard links and universal power-loss durability | Run relevant platform/filesystem fault trials. Cooperative locks do not fence arbitrary editors or hostile processes. |

Existing journeys need no migration. Update the entire skill folder together. Historical import deliberately preserves uncertainty; recovery from a complete archive deliberately leaves incomplete archives and uncertain ownership untouched.
